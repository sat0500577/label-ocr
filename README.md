# 라벨 OCR

상품 라벨 사진에서 **제품명/색상**(예: `HP딘버일자/그레이`)을 뽑아내는 개인용 웹앱.

**https://sat0500577.github.io/label-ocr/**

폰 Safari나 Chrome으로 위 주소를 열고 공유 → **홈 화면에 추가**를 하면 앱처럼 쓸 수 있다.
한 번 인식을 돌리면 엔진·모델이 폰에 캐시돼 이후에는 인터넷 없이도 동작한다.

## 어떻게 동작하나

서버가 없다. 사진 촬영·글자 인식·추출이 전부 브라우저 안에서 끝나고, 사진은 어디로도 전송되지 않는다.

1. 촬영한 사진을 긴 변 2000px로 줄이고 EXIF 회전을 바로잡는다.
2. **바코드를 지운다**(`suppressBarcode`). 가로 한 줄에서 밝기가 뒤집히는 횟수를 세면
   바코드 구간은 글자 구간의 2배 이상이고, 그런 줄이 높이의 5% 넘게 이어진다.
   바코드가 화면에 있으면 Tesseract의 레이아웃 분석이 무너져 글자를 **아예 못 읽는다**.
   덮는 색은 반드시 사진의 중간 밝기여야 한다. 흰색으로 덮으면 이진화 기준이 밀려
   나머지 글자까지 통째로 사라진다. 둘 다 실측으로 확인한 사항이다.
3. 인식 폭이 1600px가 되도록 확대한 뒤 Tesseract.js로 두 번 읽는다.
   페이지 분할은 **PSM 11(희소 텍스트)**. 라벨처럼 글자가 흩어져 있을 때 기본 모드보다 훨씬 잘 찾는다.
   한국어 모델과 영어 모델을 따로 돌린다. `kor+eng`로 한 번에 돌리면 "HP딘버일자"처럼
   영문 뒤 한글을 영문 단어로 오인해 깨뜨린다.
4. `labelFormat()`이 필요한 줄만 고른다.
   - 줄 묶기는 **Tesseract가 만든 줄 구조를 그대로 쓴다**. y좌표로 직접 묶으면 기울어진
     라벨에서 오른쪽 분류명이 왼쪽 둘째 줄과 섞인다(실측 확인).
   - 신뢰도 70 이상인 글자가 2자 미만인 줄은 포장지 잔글씨로 보고 버린다.
   - 줄 높이 중앙값의 60% 미만인 줄도 버린다. 최댓값을 쓰면 바코드 오인식 하나가 기준을 망친다.
   - 각 줄에서 왼쪽 덩어리만 취한다(줄 높이보다 넓은 간격에서 끊음). 오른쪽 `@`·분류명이 빠진다.
   - 한국어 모델은 앞머리 영문(HP)을 엉뚱한 한글로 바꾼다. 확실하게 읽힌 첫 한글보다 왼쪽은
     영어 패스의 **글자 단위 좌표**로 갈아 끼운다.
   - 제품명 = 글자가 남는 첫 줄(영문+완성형 한글만, 숫자·기호·낱자모 제거).
     색상 = 그 아래에서 왼쪽 끝이 비슷한(같은 열) 첫 줄(완성형 한글만).

자동 인식이 빗나가면 미리보기에서 글자 부분을 끌어 선택해 그 영역만 인식시킬 수 있다.
"한글만"·"전체" 모드도 있어 라벨이 아닌 사진에도 쓸 수 있다.

## 파일

```
index.html          화면·OCR 호출·추출 규칙 전체 (단일 파일)
sw.js               오프라인 캐시. vendor/는 캐시 우선, 나머지는 네트워크 우선
manifest.json       홈 화면 추가용 앱 정보
icon.png            앱 아이콘
sample-label.png    테스트용 합성 라벨
vendor/             Tesseract.js 엔진·wasm 코어·kor/eng 모델
```

`index.html`을 고쳐 다시 올릴 때는 `sw.js`의 `CACHE` 이름을 올린다(구버전 캐시 정리).

안드로이드 네이티브 앱(ML Kit 사용) 버전과 빌드 스크립트는 상위 폴더에 있다.
